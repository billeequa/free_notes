# Recovery and safe disconnect

- **Internet/server/account trouble:** continue using the phone normally. Reads, local writes, local search, exports and EPUB do not require sync. Open Settings → Web Sync for a nonblocking status. Disable sync at any time; it cancels jobs without deleting files or the cloud copy.
- **Forgot password:** on the website choose **Forgot password?**, request and open the emailed reset link, enter the recovery code saved during setup, then choose a new password. Sign in again on the phone with the new password. The recovery code and notebook key stay the same; existing phone files are preserved.
- **New phone/browser, forgot password:** use verified email plus the saved recovery code, choose a new password, and complete staged reset. The code alone cannot authenticate to the account. Web recovery is built into the login page; do not use a generic provider password form.
- **Lost Keystore/session:** cloud sync needs verification and the password or recovery code. The existing phone files are not encrypted by this mechanism and remain readable.
- **Lost email and every cloud decryption credential:** cloud recovery can be impossible. Export existing readable phone content first. Provision a new approved identity/vault only through a separately reviewed reset. The current implementation refuses to silently reuse a different cloud owner/key with an old sidecar.
- **Cloud rollback/restore:** sync freezes. Verify the host and restored backup, then on the phone type REPAIR in Web Sync. Repair first verifies a complete local backup (including sync conflict evidence), authenticates the same vault identity, re-baselines queue revisions against the restored cloud, retains differences as conflicts, resets its cursor, and resumes. It never replaces phone files during repair. A different vault key/deployment is refused.
- **Conflicting edits:** Keep Phone and Keep Web are explicit choices; Save Both creates another record. A discarded unsent variant is retained as an encrypted trashed conflict copy so the choice remains reversible after upload. Previous server versions are immutable. Restoring history/trash creates another revision.
- **Revoke access:** browser Settings → Sign out all sessions. Every protected RPC checks the live session row, so a deleted session stops database access before its JWT expires. A live malicious client could have already copied data; no revocation can erase those copies.

A normal Android export is independent of the cloud. The verified pre-sync ZIP includes existing note/task files and Trash; subsequent backups include sync recovery evidence. Cloud exports contain only encrypted records, wrapped vault envelopes and public bootstrap configuration. Keep backups separately from the machine being backed up. Preserve the original auth-user UUID because it is bound into ciphertext AAD.
